# Learning API mapping

Updated 2026-11-09. Backend: `http://deeptutor.local`. Paths below include `/api`; the shared Axios client already supplies that prefix. No backend/security configuration was changed.

## Contract evidence and scope

`GET /openapi.json` returned the frontend HTML and `/api/openapi.json` returned 404 through the development proxy. Contracts were therefore checked against `/tmp/deeptutor-ui-audit/source/deeptutor/api/routers/{mastery_path,book,reading,workspace,sessions}.py`, `core/turn_request.py`, the original frontend's `web/lib/{learning-api,book-api,book-ws-operation,reading-api,reading-workspace-api,practice-api}.ts`, and authenticated live responses. A source-verified operation is not necessarily live-tested.

All REST calls reuse `src/api/client.ts`: credentialed requests, configured server URL, 30-second timeout, and the existing AuthProvider. No credentials or cookies are placed in application storage. All Learning requests carry explicit `dt_workspace=<content workspace ID>` (empty means General). These content workspaces are distinct from Reading collection IDs. Workspace selection is remembered as an ID, scoped by server and user, through the existing preferences store. Session and activity IDs come from the server.

Errors: 401 triggers the existing sign-in flow; its return URL now retains Learning query/session/workspace parameters. 403 shows a permission error. No HTTP response is a network failure; other HTTP errors retain a textual backend detail or their status. 404, 409, and 422 are not replaced with fixtures. Failed writes retain editable input. Reads abort on blur/key changes, preventing older responses from overwriting a newer screen. Lists reload on focus and after mutations.

`COMPLETE` below means the listed narrow integration was exercised live. `PARTIAL` means code exists but some behavior or live verification remains. `BLOCKED` describes unavailable verification or infrastructure. `NOT IMPLEMENTED` identifies an actual implementation gap.

## Verification and remaining limits

See [implementation status](LEARNING_IMPLEMENTATION_STATUS.md) and [read-only browser evidence](learning/browser-readonly-report.json). Original fixtures remain in the repository for their regression/development surfaces; production Learning routes now use live code under `src/features/learning/live/`. No mock fallback is used in that code.

The browser development origin is not permitted by this backend's credentialed CORS configuration. For verification only, `scripts/learning-preview-proxy.cjs` forwards Expo and backend traffic through one local origin. This does not disable authentication or alter backend settings. Native clients continue to use the existing configurable backend URL. Android device/emulator verification is BLOCKED: no adb/device was available.
